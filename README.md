# Iran Stock Intelligence

سامانه تحلیل بنیادی بازار سرمایه ایران؛ نسخه توسعه‌ای با تمرکز اولیه بر **ساروم (سیمان ارومیه)**.

## اجرای محلی در Windows PowerShell

پیش‌نیاز: Docker Desktop و Git.

```powershell
git clone https://github.com/alinajd1377/iran-stock-intelligence.git
cd iran-stock-intelligence
Copy-Item .env.example .env
docker compose up --build
```

اگر مخزن قبلاً clone شده است:
```powershell
cd C:\Users\alina\iran-stock-intelligence
git pull origin main
docker compose up --build
```

پورت میزبان API از `.env` خوانده می‌شود؛ مقدار پیش‌فرض `HOST_API_PORT=8001` است تا با سرویس‌های محلی روی 8000 تداخل نداشته باشد. داخل کانتینر API همچنان روی 8000 گوش می‌دهد.

- داشبورد فارسی: http://localhost:8001/dashboard
- مستندات API: http://localhost:8001/docs
- سلامت API: http://localhost:8001/health
- سلامت دیتابیس: http://localhost:8001/health/db

توقف: `Ctrl+C` سپس `docker compose down`. برای حفظ اطلاعات دیتابیس از `docker compose down -v` استفاده نکنید.

## قابلیت‌های پیاده‌سازی‌شده در این مرحله

- FastAPI، PostgreSQL و Docker Compose؛ ایجاد اولیه جداول و seed نماد ساروم.
- نگهداری اطلاعیه کدال با `tracing_no` یکتا، payload خام و نسخه‌های فایل با SHA-256.
- endpoint تلاش برای همگام‌سازی اطلاعیه‌های کدال.
- دانلود فایل خام در مسیر content-addressed زیر `data/raw`.
- parser محافظه‌کار برای فایل‌های XLSX و PDF با نگاشت محدود اقلام مالی؛ داده ناشناخته حدس زده نمی‌شود.
- ذخیره fact مالی با دوره، واحد، ارز و منبع اطلاعیه.
- جداول فروش ماهانه محصول‌محور و snapshot بازار.
- محاسبه اولیه P/E، P/B و P/S بر اساس آخرین fact منتشرشده قابل دسترس و market cap ثبت‌شده/ورودی.
- ثبت سبد و دارایی‌ها، وزن بر مبنای بهای تمام‌شده و شاخص تمرکز HHI.
- سناریوی رشد مکانیکی قابل تنظیم؛ این خروجی مدل ML یا پیش‌بینی تضمینی نیست.
- کاتالوگ چهار پلن Fundamental، Fundamental Plus، Fundamental Pro و Portfolio Intelligence با دوره‌های ۳، ۶ و ۱۲ ماه.
- داشبورد فارسی RTL و مستندات تعاملی OpenAPI.
- پیکربندی اولیه Alembic و تست‌های واحد خدمات مالی.

## تست‌ها و migration

پس از build:
```powershell
docker compose exec api pytest
```

برای محیط‌های جدید و پس از بازبینی migration:
```powershell
docker compose exec api alembic upgrade head
```

در حال حاضر `create_all` برای راه‌اندازی محلی فعال است. پیش از production باید migrationهای نسخه‌بندی‌شده و فرایند deploy به‌صورت کنترل‌شده جایگزین bootstrap شوند.

## مواردی که هنوز کامل/تأیید نشده‌اند

این مخزن هنوز محصول کامل و داده‌محور قابل اتکای سرمایه‌گذاری نیست. موارد زیر صریحاً باقی مانده‌اند:

1. **کدال:** endpoint و schema پاسخ باید با نمونه‌های زنده اعتبارسنجی شوند؛ تاریخ انتشار، دوره، نوع گزارش، حسابرسی و اصلاحیه هنوز از همه انواع اطلاعیه‌ها استخراج نمی‌شوند. صفحه‌بندی و checkpoint مقاوم نیز نیازمند تکمیل است.
2. **فایل‌ها و استخراج:** parser فعلی عمومی و محدود است؛ نگاشت دقیق قالب‌های کدال، فایل‌های Excel/PDF واقعی، جداول چنددوره‌ای، واحدها، ارقام تجمعی/فصلی و بازبینی کیفیت هنوز لازم است.
3. **داده ساروم:** مجموعه تاریخی فروردین ۱۴۰۴ تا آخرین گزارش منتشرشده، صورت‌های مالی ۳/۶/۹/۱۲ ماهه و تفکیک نسخه حسابرسی‌شده/نشده هنوز به‌صورت کامل ingest و تطبیق نشده است. داده‌ای را تا زمانی که از منبع اصلی واکشی و اعتبارسنجی نشده، موجود فرض نکنید.
4. **TSETMC:** جست‌وجوی اولیه adapter وجود دارد، اما دریافت تاریخچه قیمت، تعداد سهام، سرمایه، توقف/بازگشایی و ذخیره خودکار هنوز پیاده‌سازی و با API زنده اعتبارسنجی نشده است.
5. **نسبت‌ها:** نسبت‌ها فقط بر اساس facts موجود محاسبه می‌شوند و در وضعیت فعلی الزاماً TTM استاندارد نیستند. EPS، سود/زیان فصلی با تفاضل تجمعی، تعدیل افزایش سرمایه و تاریخچه point-in-time باید تکمیل شود.
6. **گزارش ماهانه و صنعت:** استخراج تفکیکی مقدار فروش، نرخ فروش، مبلغ فروش، محصول، ظرفیت و مقایسه هم‌گروه هنوز نیازمند parser اختصاصی و داده چندنمادی است.
7. **پیش‌بینی:** فعلاً فقط سناریوی رشد مکانیکی وجود دارد؛ مدل hybrid آماری/ML، backtest و کنترل look-ahead هنوز ساخته نشده‌اند.
8. **سبد:** فعلاً ثبت دارایی و تمرکز بر اساس بهای تمام‌شده انجام می‌شود؛ بازده واقعی، نوسان، همبستگی، VaR، drawdown و پیشنهاد سبد هنوز نیست.
9. **اشتراک:** فقط کاتالوگ پلن‌ها پیاده‌سازی شده؛ کاربران، احراز هویت، مجوز دسترسی، پرداخت، تمدید، صورتحساب و کنترل bundle فعال نیست.
10. **محصول کامل:** frontend حرفه‌ای، worker صف، زمان‌بندی، مانیتورینگ، CI/CD، امنیت و تست end-to-end هنوز لازم‌اند.

## اصول صحت داده

- شناسه یکتای اطلاعیه: `tracing_no`؛ period و symbol کلید یکتا نیستند.
- نسخه‌های فایل مستقل و با checksum ثبت می‌شوند.
- حسابرسی‌شده و حسابرسی‌نشده باید اطلاعیه/نسخه مستقل داشته باشند.
- زمان انتشار، دوره مالی، زمان دریافت و زمان استخراج باید جدا بمانند.
- هر fact باید همراه واحد، ارز، دوره و منبع نگهداری شود.
- داده‌ای که تاریخ انتشار معتبر ندارد نباید در محاسبات تاریخی point-in-time استفاده شود.

این نرم‌افزار ابزار پژوهش است، نه توصیه سرمایه‌گذاری و نه تضمین صحت یا کامل‌بودن داده.


## Sarom research data

Curated research snapshot: `backend/app/data/sarom_snapshot.json`. The dataset is source-linked, distinguishes audited and unaudited six-month filings, includes the Mehr 1405 monthly sales headline and product revenue summary, and documents data gaps. It is not a substitute for downloading and validating the original Codal files.


## آرشیو خودکار و تاریخی کدال

سرویس مستقل `codal-archive` در کنار API اجرا می‌شود. این سرویس به‌صورت پیش‌فرض هر ساعت چند صفحه آخر اطلاعیه‌های نمادهای تعیین‌شده را بررسی می‌کند، اطلاعیه‌ها را با `tracing_no` یکتا ثبت می‌کند، نسخه فایل‌ها را با SHA-256 نگه می‌دارد و برای فایل‌های قابل‌خواندن، استخراج محدود facts را اجرا می‌کند. فایل خام در `data/raw/codal` باقی می‌ماند تا با ارتقای parser دوباره پردازش شود.

تنظیمات قابل افزودن به فایل `.env`:
```dotenv
CODAL_SYMBOLS=ساروم
CODAL_POLL_INTERVAL_SECONDS=3600
CODAL_INCREMENTAL_PAGES=3
CODAL_PAGE_SIZE=100
```

بعد از دریافت تغییرات و build، آرشیو تاریخی را یک بار اجرا کنید:
```powershell
docker compose stop codal-archive
docker compose run --rm codal-archive python -m app.jobs.codal_archive --backfill --pages 1000
docker compose up -d codal-archive
```
فرمان بالا از صفحه ۱ تا حداکثر ۱۰۰۰ جلو می‌رود؛ اگر کدال محدودیت یا خطا داد، لاگ را بررسی و فرمان را بعداً تکرار کنید. شناسه اطلاعیه و hash فایل مانع ثبت دوباره رکوردهای تکراری می‌شود.

وضعیت آرشیو و فهرست اطلاعیه‌ها:
- `GET /api/v1/codal/archive/status?symbol=ساروم`
- `GET /api/v1/codal/archive/announcements?symbol=ساروم&limit=100`

لاگ worker:
```powershell
docker compose logs -f codal-archive
```

**محدودیت مهم:** این نسخه آرشیو خام، نگهداری نسخه‌ها و polling دوره‌ای را اضافه می‌کند؛ اما parser فعلی فقط تعداد محدودی قلم استاندارد در XLSX/PDF را می‌شناسد. استخراج کامل تمام جدول‌ها، یادداشت‌ها، ریز فروش محصولی و تبدیل دقیق تمام واحدها هنوز تضمین‌شده نیست. گزارش‌های جدید آرشیو می‌شوند، ولی برای خواندن کامل محتوای هر فرم باید parserهای اختصاصی و تست‌شده بر اساس نمونه‌های واقعی توسعه یابد. API جست‌وجوی کدال ممکن است تغییر کند یا محدودیت دسترسی اعمال کند.

## وضعیت تکمیلی آرشیو و داشبورد (نوامبر ۲۰۲۶)

در تغییرات جدید:
- جدول `daily_fx_rates` برای ثبت نرخ روزانه ارز با تاریخ، جفت‌ارز و منبع اضافه شده است؛ ورود نرخ فعلاً دستی است و تا زمان انتخاب و اعتبارسنجی تأمین‌کننده نرخ، نرخ خودکار منتشر نمی‌شود.
- جدول `document_content_items` برای نگهداری متن صفحات PDF، سلول‌های پرشده XLSX و متن استخراج‌شده HTML اضافه شده است. فایل خام همچنان مرجع اصلی است.
- APIهای وضعیت آرشیو، فهرست گزارش‌ها، نمایش محتوای استخراج‌شده، مدیریت نماد و ثبت/خواندن نرخ ارز اضافه شده‌اند.
- دکمه دریافت دستی داشبورد از مسیر کامل آرشیو استفاده می‌کند؛ worker نیز دریافت دوره‌ای را ادامه می‌دهد.
- داشبورد بازطراحی شده و امکان افزودن/انتخاب نماد و تفکیک نمای گزارش ماهانه و دوره‌ای را دارد.

**محدودیت‌هایی که عمداً به‌عنوان تکمیل‌شده اعلام نمی‌شوند:** محتوای XLS قدیمی و PDF اسکن‌شده نیازمند تبدیل/OCR است؛ استخراج مفهومی تمام یادداشت‌ها و جداول تضمین نشده؛ نگاشت نوع گزارش کدال باید با پاسخ زنده تست شود؛ فصل مستقل دوم از تفاضل ۶ماهه و ۳ماهه هنوز در لایه تحلیل محاسبه نمی‌شود؛ نرخ دلار خودکار و نمودار مقایسه مبلغ ماه/فصل سال جاری با سال قبل و درصد رشد هنوز به داده استانداردشده نیاز دارند. نمودار مبلغ نباید با شمارش اطلاعیه‌ها یا داده فرضی جایگزین شود.

نسبت‌های قابل هدف شامل EPS، P/E، P/E TTM، P/E Forward، P/B، P/S، PEG، EV/EBITDA، EV/Sales، ROE، ROA، حاشیه سود ناخالص/عملیاتی/خالص، نسبت جاری/آنی، بدهی، بازده سود نقدی و P/FCF است. فقط نسبت‌هایی محاسبه می‌شوند که ورودی و مبنای زمانی معتبر داشته باشند؛ P/E Forward و PEG بدون برآورد مستند سود محاسبه نمی‌شوند.


## پنل‌ها و گزارش‌خوانی کدال

- پنل کاربران: `/dashboard` (قالب روشن، فهرست گزارش‌های ماهانه/میان‌دوره‌ای، نرخ ارز و کاتالوگ نسبت‌ها).
- پنل مدیریت: `/admin` (مدیریت نمادها، همگام‌سازی آرشیو، فهرست گزارش‌ها، استخراج و مشاهده شیت‌ها/جدول‌ها، نرخ ارز و پایش پوشش داده).
- استخراج جداول یک اطلاعیه از مسیر `POST /api/v1/codal/reports/{announcement_id}/extract` انجام می‌شود و خروجی از `GET /api/v1/codal/reports/{announcement_id}/tables` قابل دریافت است.
- استخراج‌کننده ابتدا شناسه شیت‌ها را از صفحه Decision کدال کشف می‌کند و سپس جدول‌های HTML هر شیت را همراه با شماره شیت، شماره جدول، سرستون‌ها و تمام ردیف‌های قابل‌خواندن ذخیره می‌کند. فایل اصلی همچنان در آرشیو خام باقی می‌ماند.
- در این مرحله خرید، پرداخت و محدودسازی امکانات بر اساس عضویت پیاده‌سازی نشده است. پنل مدیریت برای محیط توسعه است و پیش از انتشار عمومی باید احراز هویت و مجوز مدیر به آن اضافه شود.
- ایجاد جدول‌های جدید با `Base.metadata.create_all` در راه‌اندازی توسعه انجام می‌شود؛ برای محیط عملیاتی باید migration مستقل Alembic ساخته و اجرا شود.
- استخراج جدول‌های HTML به معنی تفسیر قطعی همه اقلام مالی نیست. فایل‌های قدیمی XLS، PDF اسکن‌شده و نگاشت معنایی واحد/دوره/حسابرسی به پردازش‌های اختصاصی و بازبینی نیاز دارند.
